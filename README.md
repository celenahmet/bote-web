# bote-web

Static source for `bote.web.tr`, prepared from the production web root for Vercel.
Project rules (Turkish): [CLAUDE.md](CLAUDE.md).

## Deployment

Import this repository into Vercel as an **Other** framework project. No build command is required and the repository root is the output directory. `.vercelignore` keeps unpublished pages, original images and development files (`tools/`, `content/`) out of the deployment.

The former `/blog` WordPress/PHP application is intentionally excluded. If the old WordPress tree still exists locally under `blog/`, move it out of the repository: `blog/` is now generated by the blog builder.

### View counter (Upstash Redis)

`/api/views` is a Vercel function that stores blog view counts and the "popular posts" ranking. In Vercel: **Storage → Create → Upstash for Redis** (free tier) and connect it to this project; the `KV_REST_API_URL` / `KV_REST_API_TOKEN` variables are added automatically (`UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` also work). Without them the API answers `{ "disabled": true }` and pages simply hide the counters.

## Blog and tools

Blog sources live in `content/blog/` (Markdown with YAML front matter); the generated site is written to `blog/` and committed. Drafts in `content/blog/drafts/` are never published until moved to `content/blog/posts/`.

```sh
cd tools
npm install
npm run build          # content/blog -> blog/, sitemap.xml, llms.txt, llms-full.txt, site-map pages
npm run build -- --drafts   # local preview including drafts (do not commit; run `npm run build` again)
npm run preview        # single-page review of all drafts -> tools/.preview/taslaklar.html
npm run serve          # local server emulating vercel.json + .vercelignore (http://localhost:4173)
npm test               # outputs up to date + links, SEO tags, JSON-LD, hreflang, robots/sitemap/llms, feeds, API
npm run lighthouse     # Lighthouse (SEO must be 100 on every page); add --perf for performance
```

Every post needs at least two foreign-language sources, cited in the text as `[@source-id]`; the builder refuses to build otherwise. Cover/social images are generated once into `content/blog/covers/` (needs a local Chrome; set `CHROME_PATH` if it is not found).
